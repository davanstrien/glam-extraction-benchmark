## Reproduce the generation

The [optional recipe](jobs-batch.md) records the full settings. The first model
used this command:

```bash
GLAM_JOBS_NAMESPACE=davanstrien uv run --with huggingface_hub==1.31.0 \
  examples/inference/jobs_batch.py launch --model Qwen3.5-2B --flavor l4x1
```

The other five used `--reuse-source --flavor l40sx1` with their table labels.
At most three Jobs were active or queued together. Each had a 60-minute timeout.
Generation used temperature 0, max_tokens 1600, and thinking off where supported.
NuExtract used its native extraction template; Granite used its documented KVP
prompt. The other four used the reference VLM prompt.

Runtime: vLLM 0.29.0, torch 2.13.0+cu130, Transformers 5.16.1,
huggingface_hub 1.31.0, datasets 5.0.1, and openai 3.10.0.
The Docker image was `vllm/vllm-openai:v0.29.0`. Model revisions are pinned in the
recipe and recorded in each output’s provenance and `.job.json`.

The initial L40S bootstrap failed because this image exposes `python3`, not
`python`; it ran for 50 seconds and made no inference calls. The launcher now
uses the image’s installed `uv` and `python3`. Model labels are normalized only
for Jobs tags and names; submission labels retain their original spelling.
